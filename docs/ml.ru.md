# Слой машинного обучения

Всё статистическое в этой системе — помощник. Оно предлагает тип обращения,
указывает на текст, подтверждающий значение, показывает похожие обращения и
отмечает необычные всплески. Оно никогда не меняет статус тикета, не объединяет
тикеты и ничего не отправляет клиенту. Решения принимают детерминированный
движок, YAML-схемы обращений и сотрудники поддержки — см.
[ADR 009](adr/009-ml-assists-the-deterministic-engine.ru.md).

Всё это должно работать на реальном сервере: 1 vCPU, 1.9 ГБ ОЗУ, контейнер
бэкенда 384 МБ. Это исключает запуск LLM и оставляет небольшие модели, честно
признающие, чего они не знают.

## Что работает

| Возможность | Модель | Где выполняется | Стоимость |
|---|---|---|---|
| Классификация обращения | Калиброванная логистическая регрессия по хешированным символьным n-граммам | В пути ответа | ~1 мс |
| Извлечение с подтверждением | Детерминированное сопоставление (точное, нормализованное, дата, пересечение) | В пути ответа | <1 мс |
| Эмбеддинги | `multilingual-e5-small` int8 ONNX либо хеширование символьных n-грамм | Фоновый обработчик | ~13 мс на обращение (e5) |
| Похожие и дублирующие тикеты | Косинусная близость + личность клиента + совпадение полей | По запросу | ~мс |
| Обнаружение инцидентов | Агломеративная кластеризация + пуассоновский тест всплеска | По запросу, кэш 60 с | ~мс |

Никаких платных API, внешних сервисов и векторных баз. Единственная новая
зависимость времени выполнения — numpy; ONNX-рантайм опционален.

## Классификация: сначала правила, потом модель

Порядок решения (`app/ai/providers/hybrid.py`):

1. **Правила по ключевым словам.** Явное слово о выводе или пополнении —
   детерминированное и проверяемое совпадение, оно всегда побеждает. Модель не
   может его переопределить.
2. **Классификатор** — только там, где правила ничего не нашли, и только если
   калиброванная вероятность превышает порог воздержания.
3. **Обычный запасной вариант провайдера** — то есть ровно прежнее поведение,
   включая уточняющий вопрос клиенту.

Три вещи делают вывод модели пригодным для действий:

- **Калибровка.** Сырые softmax-оценки регуляризованной линейной модели — не
  вероятности. Температура, подобранная на out-of-fold предсказаниях, приводит
  их к шкале, где «0.8» означает примерно 80% правильных ответов.
- **Отдельный класс `unclear`.** «Здравствуйте» и «у меня проблема» — это
  собственный класс в обучающих данных, поэтому модель говорит «слишком
  неопределённо» вместо того, чтобы угадывать.
- **Воздержание.** Ниже порога, выбранного по кривой риск–покрытие, предсказание
  не используется, и движок спрашивает клиента, как и раньше.

`ML_CLASSIFIER_MODE=shadow` вычисляет и записывает мнение модели, но ничего ей
не доверяет — безопасный способ оценить новую модель на реальном трафике. `off`
отключает её полностью.

## Извлечение: нет значения без подтверждения

`app/domain/evidence.py` проверяет обещание «не выдумывать значения», а не верит
ему: для каждого предложенного значения он ищет фрагмент письма клиента,
подтверждающий его, иначе движок отклоняет значение. Способы сопоставления, от
строгого к мягкому:

| Способ | Пример |
|---|---|
| `exact` | `U-482913` встречается в письме |
| `date` | `2026-09-08` подтверждается «8 сентября», «08.09.2026» или «أمس» |
| `normalized` | `U482913` подтверждается `U-482913` |
| `overlap` | свободное описание, пересказывающее письмо |

Подтверждение сохраняется вместе с полем и показывается в панели поддержки.
Проверка действует для любого провайдера, включая будущую языковую модель;
измеренная доля выдуманных значений на эталонном наборе — **0.000**.

## Эмбеддинги, похожие обращения и инциденты

Один эмбеддинг на обращение, вычисляется фоновым обработчиком (никогда не в пути
письма) и хранится в SQLite с привязкой к версии модели. Идентификаторы
маскируются до вычисления, поэтому близость определяется сутью обращения.

**Похожие тикеты** сочетают три сигнала: смысловую близость, личность клиента и
совпадение извлечённых полей. «Возможный дубликат» требует сильных доказательств
— тот же клиент и почти идентичный текст либо тот же номер транзакции. Один лишь
похожий текст даёт только «похожее».

**Инциденты** кластеризуют недавнее окно, сравнивают каждый кластер с его
собственной историей и сообщают только о всплесках с пуассоновской вероятностью
ниже 0.01. Постоянно активная тема инцидентом не считается.

Модель по умолчанию — хеширование символьных n-грамм без зависимостей.
Многоязычная модель включается одной командой:

```bash
cd backend
pip install -e ".[ml-onnx]"
python scripts/download_embedding_model.py     # ~120 МБ, проверка по SHA-256
EMBEDDING_PROVIDER=onnx                        # и поднять лимит памяти контейнера
```

С ней описания одной и той же проблемы на русском и арабском оказываются рядом:
точность кросс-языкового ближайшего соседа — 100% на тестовом наборе против 35%
у хеширования.

Это не бесплатно. Измеренный объём памяти всего процесса бэкенда:

| Конфигурация | Память |
|---|---:|
| По умолчанию (хеширование) | ~97 МБ |
| Загружена сессия ONNX | ~497 МБ |
| ONNX, батч из 256 обращений | ~503 МБ |

Почти всё — сама сессия, и она занимает память сразу при загрузке модели.
Поэтому эмбеддер ограничивает свой проход 8 текстами (`MAX_BATCH`) и отключает
арену памяти ONNX Runtime; без этого один батч из 64 текстов занимал более 1 ГБ.
**Перед включением в продакшене поднимите лимит памяти контейнера бэкенда в
`compose.yml` с 384 МБ минимум до 768 МБ** (на хосте 1.9 ГБ, из них 128 МБ —
фронтенд).

## Обучение на исправлениях сотрудников

Исправление в панели (тип обращения или одно поле) применяется как решение
сотрудника — с проверкой по схеме, `source=employee`, без изменения статуса
тикета — и записывается в `ml_feedback` вместе с исходным значением, слоем,
который его произвёл, версией модели, уверенностью, подтверждением и исходным
письмом.

Автоматического переобучения нет. `scripts/export_training_feedback.py`
выгружает маскированный набор JSONL для ревью; исключённые тикеты
(`ML_DATASET_EXCLUDED_TICKETS`) в него не попадают, демо-исправления исключены по
умолчанию.

## Оценка

`backend/scripts/evaluate_ml.py` прогоняет отложенные наборы через реальный код
и записывает [`evaluation.md`](ml/evaluation.md) и `evaluation.json`. Результат
воспроизводим: фиксированные файлы, записанные хеши, никакой случайности.

| Система | Точность | Macro-F1 | Покрытие | Точность на отвеченных |
|---|---:|---:|---:|---:|
| Правила (базовая линия) | 0.417 | 0.383 | 0.198 | 0.842 |
| Только классификатор | 0.750 | 0.761 | 0.510 | 0.980 |
| **Гибрид (работает в системе)** | **0.833** | **0.841** | **0.594** | **0.983** |

Извлечение: precision **1.000**, recall **0.868**, F1 **0.930**, доля выдуманных
значений **0.000**.

## Мониторинг

`GET /api/v1/ml/monitoring` (для сотрудников) и панель «Состояние моделей»
показывают поведение моделей на реальном трафике: объёмы по версиям, кто принял
решение, долю воздержаний, задержку, долю отклонённых значений, дрейф (PSI) и
долю исправлений сотрудников по слоям.

Отдельно стоит выделить **совпадение с правилами**: на каждом письме, которое
решило правило, мнение классификатора всё равно записывалось, поэтому их можно
непрерывно сравнивать без риска для клиентов.

## Приватность

- Идентификаторы маскируются до попадания текста в эмбеддинг, метку инцидента
  или выгрузку (`app/ml/pii.py`).
- В `ml_predictions` хранятся только метки, оценки и тайминги.
- Демо- и реальные данные всегда анализируются раздельно.
- Реальная почта по умолчанию не используется для обучения.

## Честные ограничения

- Наборы данных небольшие (366 обучающих и 96 тестовых сообщений, 24 случая
  извлечения) и написаны одним автором.
- Реальных обращений в проде пока мало, поэтому живые метрики скудны, а для
  оценки дрейфа нужны два заполненных окна.
- Калиброваны только уверенности классификатора; у правил они эвристические.
- Хеширующий эмбеддер не кросс-языковой; качество заметно растёт с
  `EMBEDDING_PROVIDER=onnx`.
- Эмбеддинги ONNX не воспроизводимы побитово: из-за int8-ядер и дополнения
  вектор слегка зависит от батча (совпадение ~0.995 по косинусу). На решения
  при текущих порогах это не влияет, но два прогона дают разные последние
  знаки. Хеширующий эмбеддер воспроизводим точно.
- Вложения не читаются, подсказок для ответов и предсказания приоритета пока нет.
