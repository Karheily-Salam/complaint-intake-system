# ADR-009 — Статистические модели помогают; решает по-прежнему детерминированный движок

**Статус:** принято

## Контекст

[ADR-002](002-deterministic-workflow-engine.ru.md) отдал все решения о ходе
диалога детерминированному движку, а [ADR-003](003-ai-provider-abstraction.ru.md)
спрятал ИИ за интерфейсом. Оба были написаны, когда слоем ИИ были правила по
ключевым словам или опциональная локальная LLM.

Появление настоящих моделей — обученного классификатора, эмбеддингов,
кластеризации — снова поднимает тот же вопрос. Модель, которая решает, может
ошибиться правдоподобно, а по тикету потом работают люди. При этом правила
измеримо слабы вне английского: macro-F1 0.383 на отложенном наборе и 0.216 на
арабском, потому что их признак «прочее» работает только по-английски.

Сервер тоже небольшой: 1 vCPU, 1.9 ГБ ОЗУ, контейнер 384 МБ и бюджет задержки
ответа около секунды.

## Решение

Модели выдают **оценённые сигналы**; решают движок, YAML-схемы и сотрудники.

1. **Правила по ключевым словам главнее классификатора.** Модель спрашивают
   только там, где правила ничего не нашли, и только выше калиброванного порога.
2. **Воздержание — полноценный исход.** «Слишком неопределённо» — обученный
   класс, а неуверенное предсказание не используется.
3. **Нет значения без подтверждения.** Каждое значение должно опираться на
   фрагмент письма клиента, иначе оно отклоняется — для любого провайдера,
   включая будущую LLM.
4. **Ничто статистическое не меняет тикет.** Похожесть подсказывает, инциденты
   предупреждают; никто ничего не объединяет, не закрывает и не отправляет.
5. **Небольшие модели в том же процессе.** Линейные модели и int8-ONNX
   эмбеддинги на CPU; без платных API, векторных БД и лишних сервисов.
6. **Тяжёлая работа — асинхронно.** В пути ответа только классификация и
   извлечение; эмбеддинги и кластеризация — в фоне или по запросу.
7. **Исправления сотрудников записываются, а не применяются к модели.**
   Переобучение — осознанный и проверяемый шаг.

## Рассмотренные альтернативы

- **Отдать решение классификатору.** Отклонено: вероятность переопределяла бы
  проверяемое совпадение по ключевому слову, а уверенная ошибка — самый дорогой
  случай.
- **Дообучить или запускать LLM для классификации.** Отклонено: не помещается в
  сервер, съедает весь бюджет задержки, и данных для честного дообучения нет.
- **Векторная база данных.** Отклонено на этом масштабе: точный перебор по
  нескольким тысячам векторов занимает миллисекунды.
- **Автоматическое переобучение на исправлениях.** Отклонено: цикл без ревью, а
  небольшая модель сильно смещается от нескольких исправлений.

## Последствия

- По сравнению с базовой линией правил гибрид примерно удваивает macro-F1
  (0.383 → 0.841) и отвечает втрое чаще, причём его ответы верны в 98% случаев.
- Точность извлечения — 1.000 при нулевой доле выдуманных значений, и для
  каждого значения видно, из каких слов оно взято.
- Появились пороги, требующие периодического пересмотра, и они зависят от
  модели: смена эмбеддера меняет и пороги.
- Эмбеддер по умолчанию не кросс-языковой, поэтому качество похожих тикетов
  ниже того, что система может дать с ONNX-моделью.
- Больше состояния в эксплуатации: таблицы эмбеддингов, предсказаний и
  исправлений, плюс фоновый обработчик.
