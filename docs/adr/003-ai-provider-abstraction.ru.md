# ADR-003 — ИИ за интерфейсом провайдера

**Статус:** принято

## Контекст

Системе нужно понимание языка, но проект для портфолио, которому для запуска
требуется платный API-ключ, — это проект, который никто не запустит, а набор
тестов, вызывающий модель, медленный и нестабильный.

## Решение

`AIProvider` — интерфейс с пятью узкими операциями: классификация, извлечение,
сводка, определение языка, составление ответа. Существуют две реализации:

- `RuleBasedAIProvider` — детерминированный, офлайн, используется по умолчанию.
- `OllamaAIProvider` — локальная LLM, включается через `AI_PROVIDER=ollama`, с
  автоматическим откатом к провайдеру на правилах, если Ollama недоступна.

## Рассмотренные альтернативы

- **Облачный API (OpenAI, Anthropic) по умолчанию.** Отклонено: стоит денег,
  требует ключа для запуска демонстрации и делает тесты недетерминированными.
  Благодаря интерфейсу добавить его позже — это новый класс, а не переработка.
- **Без абстракции, вызывать модель напрямую.** Отклонено: движок зависел бы от
  SDK поставщика, и границу из ADR-002 было бы намного труднее удерживать
  честно.

## Последствия

- `git clone && docker compose up` работает без каких-либо учётных данных.
- Набор тестов выполняется примерно за 30 секунд и полностью детерминирован.
- Провайдер на правилах действительно ограничен: он не распознаёт исправления
  уже корректных полей, потому что для этого нужно настоящее понимание языка.
  README говорит об этом прямо, а не намекает на обратное.
- Смена провайдера не меняет код движка и сервисов.
