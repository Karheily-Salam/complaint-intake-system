# ADR-008 — Публичная демонстрация изолирована от настоящих данных клиентов

**Статус:** принято

## Контекст

Проекту нужна публичная демонстрация, которой рекрутер может воспользоваться
без учётных данных, и он же обрабатывает настоящие обращения с персональными
данными: адресами, идентификаторами аккаунтов и собственными словами клиента.

Аудит обнаружил, что первая версия отдавала всё это без аутентификации по
перебираемым целочисленным идентификаторам. Более поздняя проверка выявила
более тонкую версию той же проблемы: демонстрационная точка приёма принимает
непроверенный адрес отправителя, поэтому, назвавшись адресом реального клиента,
через публичный ввод можно было изменить его запись.

## Решение

Две поверхности, разделённые в базе данных, а не в интерфейсе:

- **Публичная** — `POST /inbox` и `/demo/*`. Каждое чтение ограничено
  перепиской с флагом `is_demo` *в самом запросе*.
- **Для сотрудников** — `/tickets`, `/conversations`, `/ops/*`. Требует
  `STAFF_API_KEY`, сравниваемый за постоянное время, без значения по умолчанию:
  не задан — значит `503`, а не открытый доступ.

Личность клиента — это пара `(email, is_demo)`, поэтому демонстрационные и
настоящие клиенты остаются разными строками даже при одинаковом адресе.

## Рассмотренные альтернативы

- **Скрывать данные сотрудников во фронтенде.** Это вообще не граница: API
  по-прежнему отдавал бы их.
- **Положить API-ключ в браузерный бандл.** Ключ в JavaScript — не секрет.
  Поэтому демонстрация читает демонстрационные точки входа, а статус заявки
  доступен только для чтения.
- **Убрать демонстрацию.** Это самая убедительная часть проекта; ответ был в
  том, чтобы сделать её безопасной, а не удалить.
- **Учётные записи и роли.** Один оператор. Несоразмерно.

## Последствия

- Настоящую переписку нельзя *загрузить* через публичный API ни по какому
  идентификатору или номеру — проверено на живом экземпляре, где настоящие и
  демонстрационные записи лежали рядом.
- Демонстрационные данные действительно одноразовые: `scripts/seed_demo.py
  --reset` удаляет только демонстрационные строки, и это покрыто тестом.
- Контрактный тест маршрутов роняет сборку, если новая точка входа не отнесена
  явно к публичным или к сотрудническим, поэтому граница не может размыться по
  забывчивости.
- Всё, что введено в публичную демонстрацию, сохраняется и публично видно — так
  задумано, и README об этом говорит.
